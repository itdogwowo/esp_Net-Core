# 連線方式怎麼選：lan / wifi / bt / espnow

> **一句話**：能拉線就用 `lan`；要移動就用 `wifi`；只有一台主機要配對才用 `bt`；
> 一群裝置互相講話、又不想架 AP，才用 `espnow`。
>
> 這份文件只回答三件事：**四者差在哪、每個參數什麼意思、我該選哪個**。
> Schema 的權威定義在 [config-layers.md](../03_notes/config-layers.md)；通道怎麼實作在
> [transports.md](../01_protocol/transports.md)。

---

## 0. 三十秒決定

| 你的情況 | 選 | 為什麼 |
|---|---|---|
| 板子固定、有網線 | `lan` | 最低延遲、最穩，不跟任何人搶 2.4 GHz |
| 板子會移動，或現場只有 Wi-Fi | `wifi` | 借現成 AP，拿到 IP 就能跑 NC4 |
| 只有一支手機／電腦要連它，不想設網路 | `bt` | 配對即用，不需要 IP |
| 十幾顆裝置要互通、沒有 AP | `espnow` | 免連線、免 IP、免配對 |
| 想同時開幾個 | 全開，用 `priority` 排順序 | radio 只有一條，見 §4 |

> ⚠️ **先看你的板子**：P4 只有 `lan` 真的可用（沒有 Wi-Fi／藍牙 radio）；
> S3 沒有乙太網 PHY，主力是 `wifi` / `bt` / `espnow`。詳見 §3.2 與 §6。

**先問一句：這條連線要載 NC4 嗎？**

- **要** → 目前只有 `lan` 做得到（而只有 P4 有乙太網）；S3 的 `wifi` 是下一步。
  因為 NC4 跑在 TCP / UDP / WS 上，這三個都需要 IP，而 `bt` / `espnow` 沒有 IP。
- **不要**（只是配對、控制、OTA 輔助）→ `bt` / `espnow` 才輪得到，但它們的 transport
  目前都還沒寫（見 §6）。

## 1. 四者的分別

| | `lan` | `wifi` | `bt` | `espnow` |
|---|---|---|---|---|
| 載具 | 網線 + PHY 晶片 | 2.4 GHz Wi-Fi | 2.4 GHz 藍牙 | 2.4 GHz Wi-Fi 框 |
| 有 IP | ✅ | ✅ | ❌ | ❌ |
| 要設定什麼 | 幾乎不用（DHCP） | SSID + 密碼 | 配對碼 + 綁定金鑰 | 對端 MAC + 金鑰 |
| 典型吞吐 | **7.4 MB/s**（實測） | 未量測 | BLE 12–90 KB/s；Classic 100–200 KB/s | 單對端 100 KB/s 級，多人共享會掉 |
| 延遲 | **3.56 ms** RTT（實測） | 比 lan 高 | BLE 7.5–30 ms 起 | 低（免連線） |
| 距離 | 線有多長 | AP 的覆蓋 | 約 10 m | 約 100–200 m 空曠（與 Wi-Fi 同級） |
| 同時連幾個 | 1 條線 | 1 個 AP（ap 模式可多 client） | 1 台主機（多數情況） | **20 個 peer** |
| 誰在用 | P4 主力 | 規劃中 | 規劃中 | 規劃中 |

### 四個各一段

**`lan`（有線）**：板子用 RMII 介面接一顆乙太網 PHY（現在是 IP101），拿到 IP 之後
跟 Wi-Fi 沒兩樣，但**沒有無線的變數**：不會被鄰居的 AP 干擾、不會跟藍牙分時、RTT 穩定。
本專案量到的 7.4 MB/s / 3.56 ms 就是這條路。缺點是線。

**`wifi`（無線）**：借現場的 AP。`sta` 模式是「我去連路由器」，`ap` 模式是「我自己當熱點
讓別人連進來」，`apsta` 是兩者同時。它跟藍牙共用同一條 2.4 GHz radio，同時開會互相分時。

**`bt`（藍牙）**：**不是網路**。它是一條點對點的無線串列線，沒有 IP、沒有路由。
要拿它載 NC4，得先自己定義「怎麼把位元組裝進藍牙」（Classic 走 SPP，BLE 走 GATT），
這件事本 repo 還沒做。它的價值在「配對一次、之後自動連」，不需要任何網路設定。

**`espnow`（ESP-NOW）**：ESP32 特有的無線廣播幀，**不需要連上 AP**，直接對 MAC 丟資料。
一則最多 250 B（v2 是 1470 B），最多 20 個 peer。它跟 Wi-Fi 共用 radio 與 channel，
所以 `channel: 0` 的意思是「跟著 Wi-Fi 現在待的頻道」。

## 2. 參數逐個講

### 2.0 頂層共用

| 欄位 | 意思 | 預設 | 幾時要改 |
|---|---|---|---|
| `version` | schema 版本 | `1` | 不要改 |
| `_comment` | 給人看的說明 | — | 隨便 |
| `hostname` | DHCP 主機名 / mDNS 名稱；空 = 用 `cID` 推導 | `""` | 想在路由器清單裡認得它 |
| `priority` | 多條連線都活著時，**資料走哪條**的偏好順序 | `["lan","wifi"]` | 有線為主、無線備援就照預設 |

`priority` 只決定「都活著時用哪條」，不決定開機順序，也不決定誰先連上。

### 2.1 `lan`

| 欄位 | 意思 | 預設 | 幾時要改 |
|---|---|---|---|
| `enable` | 0/1，開不開 | `0`（P4 是 `1`） | 要用有線才開 |
| `driver` | 驅動類型，目前只有 `RMII` | `"RMII"` | 不用改 |
| `phy_type` | PHY 晶片型號（`IP101` / `LAN8720` / `RTL8201`…） | 看板子 | **換板子一定要改**，PHY 認錯就不會 link |
| `phy_addr` | PHY 在 MDIO 匯流排上的位址（0–31） | `1` | link 不起來時第一個懷疑它 |
| `gpio.mdc` / `gpio.mdio` | 管理匯流排的兩根腳 | 看板子 | 換板子 |
| `gpio.ref_clk` | RMII 的 50 MHz 參考時鐘腳；`-1` = 由 PHY 提供 | 看板子 | clock 來源不同時 |
| `ip.mode` | `static` 或 `dhcp` | `"static"`（P4） | 想要路由器發 IP 就改 `dhcp` |
| `ip.addr` / `mask` / `gw` | 靜態 IP 三件套 | 實驗室網段 | `mode: static` 時必填 |

### 2.2 `wifi`

| 欄位 | 意思 | 預設 | 幾時要改 |
|---|---|---|---|
| `enable` | 0/1 | `0` | |
| `mode` | `sta`（連別人）/ `ap`（自己當熱點）/ `apsta`（兩者） | `"sta"` | 沒有 AP 可連時用 `ap` |
| `ssid` | 要連的 AP 名稱（`sta`）或自己廣播的名稱（`ap`） | `""` | |
| `ssid_pw` | 密碼；**最終要搬進 NVS，JSON 只留空字串** | `""` | |
| `timeout_s` | 連不上時重試多久才放棄 | `300` | 現場訊號差可以拉長 |
| `ip.mode` | `dhcp` / `static` | `"dhcp"` | 要固定 IP 才改 |

### 2.3 `bt`

| 欄位 | 意思 | 預設 | 幾時要改 |
|---|---|---|---|
| `enable` | 0/1 | `0` | |
| `profile` | 拿藍牙做什麼；六個值的意思見 §3.3 | `"none"` | 要當手把就 `hid` |
| `fast` | 0 = 省電（長間隔）｜1 = 低延遲（短間隔、2M PHY） | `0` | 手把／即時控制設 1 |
| `name` | 對外顯示的藍牙名稱；空 = 用 `hostname` | `""` | 想讓手機看到好認的名字 |
| `pin` | 配對碼，空 = Just Works（雙方免輸入） | `""` | 要一層基本保護時 |
| `bonding` | 1 = 記住金鑰，配一次之後自動重連 | `1` | 每次都要重新配對才設 0 |

### 2.4 `espnow`

| 欄位 | 意思 | 預設 | 幾時要改 |
|---|---|---|---|
| `enable` | 0/1 | `0` | 依賴 Wi-Fi radio，P4 永遠不可用 |
| `channel` | 用哪個頻道；`0` = 跟隨 Wi-Fi | `0` | 沒開 Wi-Fi 時要指定（兩端必須同頻道） |
| `encrypt` | 0 = 明文，1 = 用 LMK 加密 | `0` | 正式用一定要開 |
| `pmk` | 主金鑰，用來加密各 peer 的 LMK | `""` | 開加密時設定 |
| `peers[]` | 允許通訊的對象清單 | `[]` | 每個對端一行 |
| `peers[].mac` | 對端 MAC | — | |
| `peers[].lmk` | 該對端的本機金鑰 | `""` | `encrypt: 1` 時必填 |

> ESP-NOW 最多 20 個 peer，其中加密的預設只有 7 個（可調到 17）。
> 廣播（multicast）**不支援加密**，這是協定限制。

## 3. 藍牙專章（給不熟的人）

### 3.1 兩種藍牙，不是兩種速度

| | Classic（BR/EDR） | BLE（低功耗） |
|---|---|---|
| 設計目標 | 連續高位元率：耳機、喇叭、車機 | 間歇小資料：手錶、感測器、手把 |
| 常見 profile | A2DP、HFP、SPP、HID | GATT、HOGP（BLE 版 HID） |
| 吞吐 | 100–200 KB/s | 12–90 KB/s |
| 耗電 | 高 | 低 |
| 手機支援 | 音訊類很普遍 | 幾乎全部 |

**兩者不是「快版／慢版」的關係，是兩套不同的協定**。同一支手機對它們的配對流程也不一樣。
所以 schema 拆成兩層：`profile` 說「要什麼用途」，`fast` 只是同一用途下的偏好；
真正用哪套協定由板子能力推導（見 §3.3）。

### 3.2 哪些板子做得到

| 板子 | Classic | BLE | 結果 |
|---|---|---|---|
| **ESP32-S3**（本 repo 的 S3 port） | ❌ | ✅ | 只有 BLE，只能用 `hid` / `gatt` |
| **ESP32-P4**（本 repo 主力） | ❌ | ❌ | 沒有 radio，`bt` 永遠不可用 |
| ESP32（初代，本 repo 沒有 port） | ✅ | ✅ | Classic 與 BLE 都能用 |
| ESP32-C2/C3/C5/C6 | ❌ | ✅ | 只有 BLE |
| ESP32-H4 | ❌ | ✅（含 LE Audio） | 只有 BLE，但支援 LE Audio |

所以本 repo **沒有任何一塊板子能開 Classic**——它不是設定值，是硬件事實。
在 S3 上把 `profile` 設成 `a2dp` / `hfp` / `spp`，只會在 log 看到「不支援」。

### 3.3 `profile` ＋ 板子能力 → 實際協定

沒有 `mode` 欄位。「用哪個協定」是推導出來的：

| 能力 | `profile` | `fast` | 實際 |
|---|---|---|---|
| dual（初代 ESP32） | `a2dp` / `hfp` | 任意 | Classic（只有它有） |
| dual | `hid` / `spp` | 1 | Classic（低延遲） |
| dual | `hid` / `spp` | 0 | BLE（省電） |
| ble（S3） | `hid` / `gatt` | 任意 | BLE |
| ble | `a2dp` / `hfp` / `spp` | 任意 | log 不支援 |
| none（P4） | 任意 | 任意 | log 不支援 |

**`profile` 六個值分別是什麼**

| `profile` | 全名 | 做什麼 | 對端要什麼 | S3 |
|---|---|---|---|---|
| `none` | — | 不啟用任何 profile（等於關掉） | — | ✅ |
| `hid` | Human Interface Device | 鍵盤、滑鼠、手把、簡報器 | 系統內建驅動，**免 app** | ✅ |
| `spp` | Serial Port Profile | 無線序列埠：把藍牙當位元組管道 | 舊設備／工業儀器（HC-05 那種用法） | ❌ Classic |
| `a2dp` | Advanced Audio Distribution Profile | 單向高品質音樂（手機 → 喇叭） | 耳機／喇叭／車機 | ❌ Classic |
| `hfp` | Hands-Free Profile | 雙向通話，含麥克風 | 手機通話／車機 | ❌ Classic |
| `gatt` | Generic Attribute Profile | 自訂 BLE 服務與特徵 | **你自己的 app** 或 PC 工具 | ✅ |

- 選 `hid` 的唯一理由：**對端不用寫程式**。
- 選 `gatt` 的理由：最自由，什麼資料都能塞；代價是兩邊都要自己寫。
- `spp` 常被誤會成「所有 ESP32 都能當無線 UART」——其實只有初代有 Classic。

`both`（同時開 BLE ＋ Classic）不是設定值，是初代 ESP32 的 `bt-dual` build 才有的能力；
它必須用 Bluedroid（NimBLE 只支援 BLE），RAM 與 flash 都會明顯變大。

### 3.4 `pin` 怎麼用

藍牙的配對碼有兩種長度，韌體會自動整理（每次開機讀到就正規化，結果不同就寫回檔案）：

| 你填的 | 結果 |
|---|---|
| `""` | Just Works：雙方都不用輸入（手機仍可能跳一次確認） |
| `"1234"` | 4 位 → Classic 用 `1234`；BLE 會左補 0 成 `001234` |
| `"123456"` | 6 位 → 直接使用 |
| `"12-34"` | 只取數字 → `1234` |
| `"1234567"` | 超過 6 位 → 取前 6 位 |
| `"12"` 或 `"abcd"` | 不足 4 位／沒數字 → 視為沒設定，寫回 `""` 並警告 |

**為什麼 BLE 是 6 位**：這是 BLE 協定的固定寬度（000000–999999），不是我們多存了什麼。
Classic 的 legacy PIN 則是 4 位。

### 3.5 `bonding`

`bonding: 1` = 把配對金鑰存進 NVS，下次自動重連；`0` = 每次都要重新配對。
安全性上兩者差不多，差別只在便利性。

### 3.6 藍牙不是網路

`bt` 沒有 IP。要用它載 NC4，得先決定「用哪個 profile 搬位元組」：

| 用途 | profile | 本 repo |
|---|---|---|
| 資料（仿序列埠） | Classic SPP | 未做，且 S3 不支援 |
| 資料（自訂服務） | BLE GATT | 未做 |
| 鍵盤 / 滑鼠 / 手把 | HID（BLE 走 HOGP） | 未做，但 S3 完全可行 |
| 耳機 / 麥克風 | A2DP、HFP | 未做，且 S3 不支援（只有初代 ESP32） |

## 4. 一起開會怎樣

**所有無線都共用一條 2.4 GHz radio，同一時間只有一個能發射。**

- `wifi` + `bt`：Wi-Fi 連著、BLE 也連著時，官方 coexist 是 **50/50 分時**，
  兩邊的吞吐都會掉、延遲都會升。
- `espnow` + `wifi`：本來就是同一條 radio、同一個 channel；`espnow` 的流量會跟 Wi-Fi 搶。
- `lan` + 其他：有線不吃 2.4 GHz，**這是最乾淨的組合**——有線當資料主力，
  `bt` / `espnow` 只做控制。

建議的三種組合：

| 場景 | 建議 |
|---|---|
| 固定裝置、要最大吞吐 | `lan` 開，其他全關 |
| 移動裝置、要能上網 | `wifi` 開；`bt` 只在需要配對設定時開 |
| 一組裝置互相通訊 | `espnow` 開；有 AP 的話 Wi-Fi 只當管理通道 |

## 5. 安全

- `ssid_pw` / `pmk` / `lmk` / `pin` 是秘密。最終要搬進 NVS，JSON 裡只留空字串
  （現在還沒搬，所以別把正式密碼 commit 進來）。
- `pin: ""`（Just Works）**沒有中間人保護**：附近的人可以假冒對端。
  要一層基本保護就填 4–6 位數字。
- `espnow.encrypt: 0` 是明文傳輸；廣播無論如何都不能加密。
- 有線沒有這個問題，但線本身就是邊界。

## 6. 實作現況（誠實版）

| 能力 | 狀態 |
|---|---|
| `lan` | ✅ 功能已實作並量測（P4 主力）；但參數目前寫在程式裡，還沒從 JSON 讀 |
| `wifi` | ❌ 只有 schema，firmware 沒有 Wi-Fi 程式 |
| `bt` | ❌ 沒有 BT stack（`CONFIG_BT_ENABLED` 未開），也沒有 transport |
| `espnow` | ❌ 只有 schema，transport 未做（[transports.md](../01_protocol/transports.md) 已列為 PUSH 通道） |
| `bt.pin` 正規化 | ✅ 唯一有從 `network.json` 讀的欄位 |
| 其餘欄位 | ❌ JSON 尚未被載入使用 |

也就是說：**現在把 `enable` 改成 1，什麼都不會發生**（`lan` 是程式裡寫死的，其他三個還沒接）。
這份 schema 現在的價值是「先把格式定下來」，不是「改了就會動」。
