Pixel 四層：緩衝、交接與流向

四層同時跑：effect 一路算、paint 一路交環格、encode 一路搬去 DMA、render 一路送。 緩衝之間有箭嘴標出流向（0 copy／1 copy）；任務與緩衝之間有箭嘴標出誰讀誰寫。 owner＝建立／擁有 lifetime；W／R＝誰寫／誰讀。
每格 = 一個 frame_interval（20 ms 或 5 ms）；每層的工作都縮在一個 tick 內完成，圖上只顯示 tick 邊界的狀態。

像素 copy 次數：effect→paint 0（只傳 nc_pipe_effect_frame_t 指標）、paint→環 0（layout 直接寫 slot_payload）、 環→DMA 1（encode 轉置成該硬件的線材格式）、encode→render 0（只傳 12 B 索引）、render→硬件 0（DMA 讀自己個槽）。
環的狀態機：FREE → FILLING →（commit）READY →（peek 最新）encode →（DMA 完成）release → FREE。 FILLING 只存在 begin() 與 commit() 之間（同一個 tick 內），所以圖上唔會停喺呢個狀態。 環的 struct 只有三個 state；圖上「DMA 用緊」係畫面上嘅標記 —— 事實上嗰格仍然係 READY，要等 release(seq) 才變 FREE。
4 子幀會漏格（現況，未修）：paint 每個視覺幀連續 commit 4 格（for sf in 0..ns）， 但 encode 每個 tick 只 peek 最新一格，並把其餘 READY 格直接釋放（假消費）。 所以 4 個子幀入面只有最後一個真的送去 DMA，另外 3 個消失 —— 睇上面「假消費」的計數。 呢個就係 pixel-ring-flow.md §4.2 講的張力（原本以為「下一個 tick 才補」，但 peek 會先把它們釋放）。
