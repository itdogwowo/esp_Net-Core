# docs/00_pm/ — 項目管理層

這一層只回答三個問題：**做到哪了？接下來做什麼？為什麼當初這樣決定？**

它不放技術細節。技術細節在隔壁三層。

---

## 放什麼 / 不放什麼

| 放這裡 | 不放這裡（去哪） |
|---|---|
| 現況快照（數字、已完成、卡住的事） | 協議規格 → `01_protocol/` |
| 路線圖 / 分期 / 里程碑 | 操作步驟、怎麼 build、怎麼測 → `02_guides/` |
| 決策紀錄（選了什麼、放棄什麼、代價） | 設計原理、架構推導 → `03_notes/` |
| 待辦、風險、開放決策 | 程式碼 → `firmware/` |

判準：**「這件事讀完會不會讓你少寫一行程式？」**
會 → 那是 `03_notes/`。不會、但會讓你少走一段冤枉路 → 才是這裡。

---

## 現有文件

| 文件 | 性質 | 更新時機 |
|---|---|---|
| [status.md](status.md) | **快照**：現在的數字與狀態 | 每次量測 / 每個 Phase 結束 |
| [roadmap.md](roadmap.md) | **計劃**：Phase 0–5、非目標、開放決策 | 改變優先順序時 |

### 維護規則

`status.md` 是**快照，不是日誌**。更新時直接覆蓋舊數字，並改最上面的「最後更新」日期。
想留歷史請看 git log —— 不要把過期數字堆在同一頁，那正是「不知道哪個才是真的」的來源。

`roadmap.md` 只記「還沒做／已定案」的決定。做完的項目移到 `status.md` 的已完成區，
或直接刪掉（git 有紀錄）。

## 之後可能要加的

目前只有兩份。當專案變大時，這幾種東西值得獨立成檔：

- `decisions/` — 架構決策紀錄（ADR）：一頁一個「為什麼選 A 不選 B」，格式固定
  （背景 / 選項 / 決定 / 代價）。目前散在 `roadmap.md` 的「開放決策」與各篇 notes 裡。
- `backlog.md` — 沒有排進 Phase 的雜項（nice-to-have、技術債）。
- `CHANGELOG.md` — 對外版本的變更紀錄（現在還沒有對外版本，先不需要）。
