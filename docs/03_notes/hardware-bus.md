# 硬體管理：目前是人工分配，不是執行期仲裁

> **狀態**：設計紀錄，**未實作**（2026-11-02）。目前沒有這個程式，也不該現在做。
> 這份說明「為什麼現階段不需要」、「分配實際上在哪裡做」，以及「哪天要做時長什麼樣、放哪一層」。

---

## 1. 現在的做法：在裝配層分配好，人工管理

硬體的所有權在**寫 code 的時候**就決定了，不是執行期搶來的：

| 在哪裡決定 | 例子 |
|---|---|
| `main.c` 的任務表 | `nc4` 擁有 parser 緩衝與兩條 decode loop；`fx` 擁有 arena 與 render loop |
| 各 component 的 `on_start()` | `store` 擁有 FAT 的切換權；`file_action` 只透過它讀寫 |
| 裝置宣告（未來的 `hw/`） | 哪個 driver 用哪條 SPI / 哪幾隻腳 |

三條規矩（review 時看這三條就夠）：

1. **一個裝置 / 一條 bus 只有一個 owner**（component 或任務）。
2. 別的模組要用，**透過 owner 提供的介面**（`provides[]`、hub、或之後的 hw 佇列）。
3. 同一條 bus 上掛多個裝置（SPI 上 TFT + SD）時，**CS 與時序由 bus 的 owner 管**，
   不是兩個模組各自拉 CS。

這跟舊專案是同一個做法：`bus.gpio_claim()` 是**開機時的檢查**，
真正「誰用哪隻腳」是設計時人決定的，不是執行期投票。

**所以「兩個核同時碰同一個週邊」在目前不會發生** —— 不是靠鎖，
而是因為**根本沒有第二個 owner**。

---

## 2. 為什麼現在不做硬體管理器

| 理由 | 說明 |
|---|---|
| 沒有衝突要解 | 加一條佇列只會多一次 copy + 一次喚醒，換不到任何正確性 |
| 會讓 debug 變難 | 呼叫變成非同步，出錯要追 `seq`，而不是看 stack |
| 現在的量測數字會被污染 | 每次硬體存取多一層排隊延遲，還沒有人需要它 |
| 之後要做時不需要重寫什麼 | 只要「一個裝置一個 owner」這條規矩還在，之後補管理器是加法，不是重構 |

**結論：等真的有共享再開工。** 在那之前，把分配寫清楚、review 有看，就夠了。

## 3. 哪天要做：放哪一層

**不是 `sys/`。** 它是一個「跑起來的任務 + 政策」，屬於 **task 層**：

```text
firmware/components/
├─ hw/           driver：暫存器、時序、匯流排（直接碰硬體）
├─ sys/          協議、記憶體、任務管理器、FAT、通道
└─ tasks/        ★ 這裡才是硬體管理器該放的地方（未來）
   └─ hw/        每核一個 loop，負責把命令排隊送給 driver
```

也就是說：`nc_hw` 若真的要做，位置是 `components/tasks/hw/`，
**不是** 上一版放在 `components/sys/hw/` 那樣 —— 那是分類錯了。

形狀先記著（不要做）：

- 每個核心一個 hw loop；**一個裝置只屬於一個核心**（註冊時指定）。
- 中間緩衝＝每核一條佇列；命令固定 16 B（`dev / op / seq / a0..a2`）。
- 大塊資料走 `nc_hub`，不進命令。
- `submit`（不等結果）/ `call`（`seq` + 號誌等結果）。
- 只有在「同一裝置必須被兩個 owner 使用」時才有意義。

---

## 4. 觸發條件（出現任何一條才開工）

1. 同一條 bus 真的被兩個模組共用（例如 TFT 與 SD 共用 SPI1，且都要非同步）。
2. 第二個核心需要驅動同一個週邊（不是「兩個 task」，是**兩個 owner**）。
3. 出現「誰在什麼時候碰了硬體」查不出來的 bug，而且 log 已經不夠。

在那之前：分配寫在裝配層，review 檢查「一個裝置一個 owner」。

---

## 5. 跟任務管理器的分工（現在就成立）

| | 管什麼 | 現在的狀態 |
|---|---|---|
| 任務管理器 `nc_task_*` | 誰跑、跑哪一核、哪一層、多久一次、量測 | ✅ 已實作 |
| 硬體所有權 | 哪個 component / 任務擁有哪個裝置 | ✅ 裝配層人工分配 |

**任務的 core 可以自由選**：因為硬體存取本來就只有一個 owner，
把 task 釘到某核並不會讓它「更安全」——這正是上一輪拿掉 `hw` 強制 core 的原因。
