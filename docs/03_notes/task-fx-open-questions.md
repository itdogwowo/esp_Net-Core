## 2. 我會這樣決定（你可以反對）

**Q-A 目錄**：已定 → 效果 `/data/pixel/effects/`、任務 `/data/tasks/`。

**Q-B 檔案失蹤**：撤回。你講咗兩個命名空間，同名唔算撞；檔案被用戶刪咗就係佢自己嘅事，
系統只要 log 一句「檔案不見了」就夠，唔需要設計一套狀態。

**Q-C 即時生效**：已定 → **開機一次**。唔監察 config 改動；要套用就重開機。

**Q-D `prio`**：定案 —— 唔入 config，固件決定；**之後再微調**（等睇到實際效果先）。

**Q-E `stack`**：定案 —— **任務自己宣告需求**（C 宣告或 manifest），
**管理器決定並分配**；唔入 config。太小會 overflow、太大浪費內部 RAM，兩者都由管理器把關。

## 4. 我自己答咗嘅（唔再問你）

- **`cmds`**：v0 唔註冊，manifest 呢個欄位暫時只係紀錄。
- **效果參數**：v0 冇 API，`nc_fx_abi.h` 嗰 16 個 f32 留位。
- **abi 降級**：唔做。
- **attach cleanup**：我會收成單一出口，唔使問。
- **detach**：同 Q-C 同一件事——要即時生效就要有卸載；唔要就開機一次定生死。
